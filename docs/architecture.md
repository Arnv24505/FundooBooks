# Architecture

## Goal
Browse, buy and track books. Catalogue data comes from Gutendex (metadata only); price, stock and ratings are storefront fields managed by the admin and clearly marked as demo data when generated by the importer.

## Three tiers
1. **Client**: Next.js App Router + React 19. Redux Toolkit owns auth/guest-cart state; TanStack Query owns server state (catalogue, cart, wishlist, orders, admin).
2. **Server**: Next.js Route Handlers. Flow: Route Handler → validation (Zod) → service → Mongoose. Handlers also enforce host checks, rate limits, authentication and authorization.
3. **Database**: MongoDB Atlas (database `Bookstore`).

```
Browser
  ├── App Router pages (server components where possible)
  ├── TanStack Query → Axios (`/api`) → Route Handlers → services → Mongoose
  └── Redux (session user + guest cart) → localStorage for guest cart
```

## Key decisions
| Decision | Why |
|---|---|
| MongoDB Atlas, not local `mongod` | Same database in development, CI and Vercel |
| Business logic in `src/services` | Route handlers stay thin and services are testable |
| JWT in an HTTP-only cookie | XSS cannot read the session; `sameSite=lax` blocks cross-site writes |
| `tokenVersion` claim | Password change/reset invalidates every previously issued token |
| Server-side authorization in every handler | `proxy.ts` is an optimistic page redirect only, never the security boundary |
| Redux for the guest cart | Guests can shop without an account; cart merges into MongoDB after login |
| TanStack Query for server state | Cache, retries, invalidation and infinite scrolling with little boilerplate |
| Route Handlers over Server Actions | Explicit HTTP API, reusable by the documented Swagger surface |
| Demo storefront fields | Gutendex has no prices/stock; derived values are deterministic and `isDemoData: true` |

## Authentication
1. `POST /api/auth/register` or `/login` verifies credentials, queues an email and signs a JWT (`sub`, `role`, `tv`).
2. The token is stored in the `bookstore_session` cookie (`httpOnly`, `sameSite=lax`, `secure` in production, max-age from `JWT_EXPIRES_IN`).
3. `getCurrentUser()` verifies the signature, loads the user and compares `tokenVersion`, so revoked sessions fail.
4. Google OAuth uses the authorization-code flow with a state cookie and exchanges the code server-side.
5. Page guards in `src/proxy.ts` redirect signed-out visitors from `/profile`, `/orders` and `/admin`; admin pages also require `role === "admin"`. `/cart` and `/wishlist` render their own signed-out states and redirect to login when an action needs a session.
6. Auth-page navigation is guarded so authenticated users do not return to login/signup: `src/proxy.ts` matches `/login` and `/signup` and redirects an authenticated session to a safe `next` path (default `/`); login/signup clients also redirect authenticated users (`auth.ready && auth.user`) and use `router.replace(...)` after successful auth/guest-cart merge, replacing the auth entry in browser history.
7. Admin role changes (`PATCH /api/admin/users/{id}`) reject self-edits and demoting the last admin, and increment the target's `tokenVersion` so stale sessions cannot keep the old role.

## Data model
| Collection | Purpose |
|---|---|
| `books` | Gutendex metadata + storefront fields (`price`, `originalPrice`, `stock`, `rating`, `reviewCount`, `isDemoData`) |
| `users` | Local/Google accounts, role, `tokenVersion`, last login |
| `carts` | One server cart per user with book snapshots |
| `wishlists` | Book ids per user |
| `addresses` | Saved Indian delivery addresses, one default |
| `orders` | Immutable item snapshots, address copy, totals, status history |
| `reviews` | One review per user/book (upsert) |
| `passwordresettokens` | SHA-256 token hashes with expiry and single use |
| `emailjobs` | Queued/attempted transactional emails |
| `stockalerts` | “Notify me” requests for out-of-stock books |

**Why these three collections exist (simple):**
- **`passwordresettokens`**: A reset link must work in a *later* request and only for a short time. The app stores a **hash** of the token (not the real token), marks it **used** after reset, and MongoDB **auto-deletes** expired rows (TTL). A JWT with only `exp` can’t easily be made single-use or revoked without server state.
- **`emailjobs`**: Emails are sent after the web response so checkout/login don’t feel slow. The DB keeps a **receipt** (queued/sent/skipped/failed). If SMTP isn’t set up, the job is marked **skipped** so the app still works locally.
- **`stockalerts`**: When a book is out of stock, the user’s “notify me” request must be **saved** until the book is back. When stock returns, the app emails waiting users and marks them notified.

They are normal production collections (they appear when those features run). Keep MongoDB access locked down and avoid exposing their raw data through public APIs.

Indexes: `books.sourceId` unique; `books.isbn`, `books.title`, `books.authors.name`, `books.subjects`; `users.email` unique; `users.googleId` sparse unique; `users.role`; order and review lookups by user/book.

## Catalogue and caching
- Pagination is DB-backed (`skip`/`limit` + `countDocuments`), never an in-memory slice.
- The catalogue renders 12 books per page with XD-style numbered pagination (84 pages for 1,000 books); page and filters live in the URL.
- An `IntersectionObserver` sentinel prefetches the next page through TanStack Query (`prefetchQuery`), so numbered paging and the next-page jump are instant. TanStack keeps the previous page visible while a new page loads.
- The catalogue already caches server state in TanStack Query; book lists are marked `Cache-Control: public, s-maxage=120, stale-while-revalidate=600`. Facets are cached for 10 minutes. Mutations invalidate the relevant keys, including admin edits/deletes.
- `npm run import:books` upserts exactly 1,000 Gutendex records by `sourceId`; `npm run refresh:books` regenerates the deterministic demo storefront fields (currently 948 in stock, 52 out of stock).

## Money
- All amounts are whole Indian Rupees.
- `src/lib/money.ts` is the single source for formatting (`formatINR`), shipping (`FREE_SHIPPING_THRESHOLD = Rs. 499`, `STANDARD_SHIPPING_FEE = Rs. 49`), and deterministic demo price/stock/rating.
- Not a single component formats currency by hand.

## Email
`queueEmail()` writes an `EmailJob`, renders the template and schedules delivery with `after()` so the HTTP response is not blocked. Without SMTP configuration the job is marked `skipped`, keeping local auth/checkout flows usable.

## Error handling
- `ApiError(status, message, details?)` maps to a consistent JSON envelope:
  `{ "success": false, "error": { "message": "...", "details": [...] } }`.
- Zod issues become `details: [{ field, message }]`, which the UI maps onto Ant Design form fields.
- Unexpected errors are logged with Winston and returned as a generic 500 without leaking internals.

## Rendering and the App Router
- Guest-facing pages render on the client where they need query state; the catalogue entry page wraps its client in `Suspense` because it reads `useSearchParams`.
- Admin pages are client-side under a shared `AdminShell`; the `/admin` layout is server-rendered with `robots: noindex`. The books list supports create (modal) and delete; editing a catalogue book uses a dedicated page at `/admin/books/[id]` backed by `GET/PATCH /api/admin/books/:id` so the form loads full book data and avoids modal/form lifecycle issues.

- Next 16 route types are generated after a build; dynamic pages declare `params: Promise<{ id: string }>` explicitly.
